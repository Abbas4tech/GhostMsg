# Redesign & Mobile-Responsiveness Progress (handoff for agents)

**Read this before touching typography, spacing, motion, mobile layout, Toaster, Command Palette or Sidebar.** It tracks an in-progress effort to align the app with the Claude Design handoff at `ghostmsg-handoff/ghostmsg-handoff/` (gitignored, local-only — ask the user for a fresh copy if it's missing). That folder's `HANDOFF.md` is the source brief; `screenshots/` are the visual targets; `reference/boards/*.dc.html` + `ghostmsg.css` have exact CSS values (padding, radius, font-size) — read those for *measurements*, never copy their markup.

Canonical docs this work feeds: [Chapter 13](../13-design-system-and-theming.md) (tokens, already updated), [Chapter 11](../11-component-registry.md) (regenerate with `pnpm docs:registry` after adding elements).

## 1. Why this exists

The handoff's suggested build order has 6 steps: **1** foundations (tokens), **2** base shadcn parts + cva variants, **3** compositions, **4** screens mobile-first then desktop, **5** motion pass, **6** trust & safety/UX details. This doc picks up partway through step 4, after 1–3 were substantially done in earlier sessions (see `docs/13-design-system-and-theming.md` and `docs/adr/0022-*.md` / `0023-*.md` for that history).

The user's own framing for this round: *"Make sure all components and mobile designs completely align with our implementation"* — then, after a side-by-side screenshot review, gave specific per-component findings (see §4) and one explicit decision: **Settings sections become collapsible/accordion on mobile**, not separate routes/drawers.

## 5. Working notes for whoever picks this up

- **Pre-existing lint baseline**: `pnpm check` / `biome check` currently reports ~194 errors repo-wide (`noRedundantDefaultExport`, `noJsxPropsBind`, `noAwaitInLoops`, etc.) that **predate this entire effort** — verified via `git stash` against the last commit, which showed the same categories (actually worse, ~2300, dominated by CRLF-vs-LF noise from `git stash`'s checkout). Don't try to fix these as part of design work; it's a separate, large pre-existing cleanup. Do check that *your* changes don't add new categories — filter the `biome check` output against `git diff` on the files you touched to confirm you're only seeing the same pre-existing rule names.
- **A Biome/formatter hook runs after every `Edit`/`Write`** and aggressively strips unused imports. If you add `import { Foo } from "..."` before you've written the JSX that uses `Foo`, the import gets silently deleted before your next edit. Reliable order: add the **usage** first (creates a harmless "undeclared variable" state), then add the **import** as a separate, final edit.
- **Full-page story-test runs are unreliable on this machine** — two separate full `vitest run --project storybook` attempts (full suite, ~100+ files) both produced cascading `chrome-headless-shell` timeouts/crashes partway through, with different random files failing each time. Running the **same files in smaller scoped batches** (10–15 files at a time) was reliable and fast. Don't trust a full-suite red run as a real signal; re-run the specific failing files scoped before concluding something broke.
- **Screenshot technique that works**: a one-off Node script in the project root (not the scratchpad — needs `node_modules/playwright` resolution) driving Playwright against either the live dev server (`pnpm dev`, port 3000) or Storybook (`pnpm storybook`, port 6006, use `iframe.html?id=<story-id>&viewMode=story&globals=theme:dark` to skip the Storybook UI chrome and force dark mode). Delete the temp script after. Always `taskkill //F //IM node.exe` when done with a dev/storybook session — orphaned processes accumulate fast across a long session.
- The design's exact measurements live in `ghostmsg-handoff/ghostmsg-handoff/reference/boards/ghostmsg.css` — grep it before guessing a padding/radius/font-size value.
